# Support Service — API обращений в поддержку

## Назначение проекта

Позволяет клиентскому интерфейсу отправлять обращение и показывать пользователю список его обращений.

## Функциональность

Создание обращения с темой и сообщением. Получение списка обращений, отфильтрованного по пользователю. В модели предусмотрен статус.

## Архитектура

`main.py` читает `X-User-Id` и обращается к PostgreSQL через асинхронный SQLAlchemy. `models.py` и `schemas.py` описывают хранение и HTTP-контракт. Внешние API и очереди отсутствуют.

## Технологический стек

Python 3.11, FastAPI, Pydantic, SQLAlchemy, asyncpg, PostgreSQL, Alembic, Docker Compose.

## Технические решения

Пользователь без `X-User-Id` получает 401. Фильтр user_id ограничивает список. Обработчики используют сессию БД через FastAPI Depends.

## Запуск проекта

Задайте `DATABASE_URL`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`. Подключите сеть `saas_network` и доверенный шлюз. Запуск — `docker compose up --build`. API опубликован на 8010. Стартовый скрипт вызывает `alembic upgrade head`. Приложение также создаёт отсутствующие таблицы через `metadata.create_all`. TODO — согласовать эти два механизма и проверить чистую БД.

## Примеры API

`POST /tickets/` принимает subject и message. `GET /tickets/` возвращает обращения пользователя. Следующий запрос без заголовка подходит для проверки 401.

```bash
curl -i http://localhost:8010/tickets/
```

Следующий запрос предназначен для тестового окружения с подготовленными данными.

```bash
curl -i http://localhost:8010/tickets/ \
  -H 'Content-Type: application/json' \
  -H 'X-User-Id: 1' \
  -d '{"subject":"Тестовое обращение","message":"Сообщение для локальной проверки"}'
```
